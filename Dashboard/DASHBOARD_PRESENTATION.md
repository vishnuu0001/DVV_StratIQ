# Strat-Aqorynth ITSM Intelligence Suite - Dashboard + Novastra-ITSM

---

## What Is Strat-Aqorynth?

Strat-Aqorynth combines two AI-powered ITSM modules that work together as an enterprise-owned intelligence layer on top of ServiceNow data:

- **Strat-Aqorynth Dashboard** turns incidents, changes, and service requests into executive visibility, SLA risk intelligence, capacity insight, and automation opportunities.
- **Novastra-ITSM** turns historical tickets, knowledge documents, screenshots, and ServiceNow records into grounded resolution guidance using local RAG and Ollama LLMs.

Together, these modules keep ServiceNow as the system of record while giving IT operations a faster, more flexible, and locally controlled AI decision layer. The key differentiator is that the intelligence runs with **Ollama local source LLMs**, so sensitive ticket data, operational patterns, work notes, RCA signals, and executive summaries stay inside the enterprise environment instead of being sent to OpenAI or external ServiceNow AI services.

## Architecture at a Glance

```
ServiceNow / Ticket Dumps / Documents / Screenshots
              |
              v
   FastAPI Backends - Dashboard + Novastra-ITSM
              |
              +--> Local Data Processing: pandas, KPI engine, ticket normalization
              +--> Local Retrieval: LanceDB / Qdrant / pgvector vector search
              +--> Local LLM: Ollama models for insights, enrichment, and RAG answers
              |
              v
     React Frontends - Executive Dashboard + Novastra-ITSM UI
```

**Dashboard frontend:** React 18 + Vite + TailwindCSS - runs on `localhost:5178`  
**Dashboard backend:** FastAPI + Uvicorn - runs on `localhost:8087`  
**Novastra-ITSM frontend:** React 18 + Vite + TailwindCSS  
**Novastra-ITSM backend:** FastAPI + RAG pipeline - runs on `localhost:8086`  
**LLM runtime:** Ollama local models such as `qwen2.5:7b`, `mistral`, and local embedding models  
**Vector storage:** LanceDB, Qdrant, and pgvector support depending on configuration  
**Fallbacks:** XLSX offline dashboard mode, rule-based insight fallback, fast grounded search fallback, and optional OpenAI provider only when explicitly configured

## Key Differentiating Features

### 1. Local AI Without External Data Exposure

- Ollama runs on-premise, with GPU acceleration and CPU fallback.
- Ticket data, operational summaries, RCA notes, screenshots, and prompts remain inside the local environment.
- OpenAI is optional, not mandatory.
- ServiceNow is used as a data source, not as the only intelligence engine.

**Why adopt:** This provides AI capability with stronger privacy, lower vendor dependency, predictable cost, and better control over model selection.

---

### 2. Dashboard - Executive ITSM Intelligence

**The command center for IT leadership.**

- **Operational Health Gauge** - Overall risk status derived from SLA compliance, MTTR, and open P1/P2 incidents.
- **Critical Alert Ticker** - Persistent P1/P2 alert banner, survivable across backend restarts.
- **Summary KPIs** - Total tickets, SLA compliance, MTTR, emergency change percentage, and service request backlog.
- **Recent Incidents List** - High-priority incidents with status and priority tags.
- **AI Leadership Insights Panel** - Natural language summaries generated by the local Ollama LLM.
- **Monthly Volume Trends** - Incident, change, and service request volume trends over time.

**Why adopt:** Leaders get a board-ready operational view in minutes without waiting for manual reporting cycles.

---

### 3. Dashboard - Incident, Change, SLA, and Capacity Analytics

- **Incident Command** - MTTR trends, priority distribution, application hotspots, aging analysis, repeat incidents, and RCA ownership.
- **Service Requests** - Open request count, aging backlog, cycle time, priority mix, and workload distribution.
- **Change Risk** - Emergency change percentage, change type trends, risk distribution, priority breakdown, and implementation cycle time.
- **SLA / KPI Dashboard** - SLA breach risk, breach rate metrics, and trend-based compliance forecasting.
- **People & Capacity** - Team workload distribution and load classification as Optimal, High, or Overloaded.
- **Ad-Hoc vs BAU** - Separates planned work from reactive operational demand.

**Why adopt:** The Dashboard moves ITSM from reactive reporting to proactive operational management.

---

### 4. Dashboard - Automation Mining and ROI Discovery

**The strongest business-value differentiator in the Dashboard module.**

- Analyzes incidents, changes, and service requests for repetitive, high-volume, long-cycle patterns.
- Scores candidates using volume, repetition, cycle time, assignment group load, complexity, and aging.
- Uses Ollama to enrich each candidate with:
  - Automation type classification
  - Opportunity score
  - Confidence score
  - Risk level
  - Rationale
  - Recommended next step
  - Estimated monthly effort savings
- Pre-warms LLM cache after data sync so insights are ready quickly.

**Why adopt:** It creates a ranked automation investment roadmap without weeks of manual process mining.

---

### 5. Novastra-ITSM - Grounded Resolution Assistant

**The operational support layer for analysts and resolver groups.**

- RAG-powered answers from indexed knowledge sources.
- Source citations and confidence scoring for every response.
- Anti-hallucination controls using relevance gates, context-only prompting, temperature zero, exact metadata lookup, reranking, and response validation.
- Similar historical incident discovery.
- Direct resolution extraction from prior work notes and solution chunks before using the LLM.
- Fast grounded fallback when full LLM analysis times out.

**Why adopt:** Analysts get resolution recommendations grounded in enterprise history instead of generic chatbot answers.

---

### 6. Novastra-ITSM - Flexible Knowledge Ingestion

- Live ServiceNow ticket fetch and resolution.
- One-time ServiceNow sync with background job tracking.
- Manual ticket entry when ServiceNow is unavailable.
- Screenshot-based ticket resolution using OCR.
- Upload and indexing of `.docx`, `.xlsx`, `.csv`, `.txt`, `.pdf`, `.md`, `.png`, and `.jpg` sources.
- Local folder, SharePoint, URL, and file-based data source support.
- Chat history, feedback collection, admin indexing, and knowledge graph views.

**Why adopt:** The module can reuse knowledge from ServiceNow, documents, ticket dumps, screenshots, and local repositories rather than relying only on live ServiceNow APIs.

---

### 7. Novastra-ITSM - Local Vector Store and Search Flexibility

- LanceDB support for local file-based vector storage.
- GPU-accelerated embedding generation with CPU fallback.
- Qdrant and pgvector compatibility retained for migration and fallback.
- Hybrid retrieval: exact metadata search, vector similarity, keyword search, regex signal search, and solution-chunk augmentation.
- Search/RAG APIs for semantic answer generation and incident analysis.

**Why adopt:** This gives the enterprise control over indexing, retrieval, storage, and migration strategy without being locked into a single vector database or vendor platform.

## Why Ollama Local LLMs Instead of ServiceNow AI or OpenAI?

| Decision Factor | ServiceNow-Only / OpenAI-Only | Strat-Aqorynth with Ollama Local LLMs |
|---|---|---|
| Data privacy | Sensitive tickets may depend on external AI processing or platform-specific controls | Prompts, embeddings, and generated insights stay local |
| Cost model | Licensing or token usage can scale with volume | Predictable local infrastructure cost after setup |
| Customization | Constrained by platform capabilities and release cycles | Prompts, scoring models, retrieval logic, and dashboards can be customized directly |
| Availability | Dependent on vendor API availability and network access | Local inference continues when external AI services are unavailable |
| Knowledge coverage | Often limited to configured platform data | Can combine ServiceNow, documents, Excel dumps, screenshots, local files, and indexed historical fixes |
| Governance | External model/provider review may be required | Enterprise-controlled runtime, models, logs, and data retention |
| Vendor lock-in | Higher dependency on ServiceNow AI or OpenAI | ServiceNow remains source of record; Strat-Aqorynth owns the intelligence layer |

## Cross-Cutting Capabilities

### Real-Time and On-Demand Data Sync

- Dashboard auto-syncs with ServiceNow on a scheduled cycle.
- Manual sync trigger is available from dashboard screens.
- Novastra-ITSM supports one-time ServiceNow sync and sync-status tracking.
- Offline XLSX fallback supports demos, testing, and analysis without live ServiceNow access.

### AI Insights and RAG Engine

- Dashboard generates leadership insights and automation enrichment with local Ollama.
- Novastra-ITSM generates grounded answers from retrieved context.
- Caching and pre-warming reduce repeated inference latency.
- Rule-based and grounded-search fallbacks keep the experience usable when LLM calls fail or time out.

### Governance and Trust

- Source citations, confidence scores, relevance gates, and response validation reduce hallucination risk.
- ServiceNow credentials are held in backend configuration, not exposed to the frontend.
- CORS, SSL verification, and environment-based settings are configurable.
- Feedback APIs support continuous quality measurement.

## Adoption Justification

1. **ServiceNow remains the source of truth; Strat-Aqorynth becomes the intelligence layer.** This avoids replacing the ITSM platform while adding tailored AI, analytics, and resolution intelligence.
2. **Local Ollama LLMs reduce data exposure.** Sensitive operational data does not need to be sent to OpenAI or external AI services for every insight or answer.
3. **The two modules cover both leadership and resolver needs.** Dashboard helps leaders decide where to act; Novastra-ITSM helps analysts resolve incidents faster.
4. **Automation ROI becomes measurable.** Dashboard identifies and scores candidates, while Novastra-ITSM reveals repeat patterns and historical fixes that support automation design.
5. **The platform is resilient.** Offline data loading, fallback insights, cached LLM outputs, and multiple vector backends reduce dependency on any single service.
6. **The solution is customizable.** KPI logic, scoring models, prompts, retrieval rules, and dashboards can be adapted to enterprise-specific ITSM processes.
